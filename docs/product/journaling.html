Journaling MVP

Implemented Validation-first

Plain-text daily journaling, optional mood tracking, monthly calendar view. Ship the smallest possible version to prove users will write daily — then let data decide what to expand.

Validation Hypothesis

Mood Adoption
40%

Scope

✅ In MVP

  • Write tab: auto-resizing textarea, optional mood picker, "Need a prompt?" button, save for today
  • History: paginated list of recent entries below the editor
  • Calendar tab: monthly grid colored by mood; gray = no entry; click a day to view it
  • Reward: +1 mana per calendar day; streak counter for motivation

Database Schema

prismaprisma/schema.prisma
model JournalEntry {
  id        String    @id @default(uuid()) @db.Uuid
  userId    String
  content   String    @db.Text
  mood      String?   @db.VarChar(20)
  createdAt DateTime  @default(now()) @db.Timestamp(6)
  updatedAt DateTime  @updatedAt @db.Timestamp(6)
  deletedAt DateTime? @db.Timestamp(6)

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, createdAt])
  @@map("journal_entries")
}
Key Decisions
  • mood is nullable varchar (not a Prisma enum) — avoids migrations when adding moods
  • Soft delete via deletedAt
  • No type, lastCapsuleViewedAt, or review/capsule fields in MVP

Weekly Analytics SQL

sqlActivation — % of users who write within 7 days
SELECT
  COUNT(DISTINCT user_id) FILTER (WHERE entry_count > 0) * 100.0
  / NULLIF(COUNT(DISTINCT user_id), 0)
FROM (
  SELECT user_id, COUNT(*) as entry_count
  FROM journal_entries
  WHERE created_at > NOW() - INTERVAL '7 days'
  GROUP BY user_id
) x;
sql7-day Retention Cohort
WITH first_entries AS (
  SELECT user_id, MIN(created_at)::date as first_date
  FROM journal_entries
  GROUP BY user_id
)
SELECT
  first_date,
  COUNT(*) as cohort_size,
  COUNT(*) FILTER (WHERE second_date <= first_date + 7) * 100.0
  / COUNT(*) as retention_7d
FROM first_entries
LEFT JOIN LATERAL (
  SELECT MIN(created_at)::date as second_date
  FROM journal_entries j2
  WHERE j2.user_id = first_entries.user_id
    AND j2.created_at::date > first_entries.first_date
) second ON true
GROUP BY first_date;

Implementation Phases

Phase 1 — 2 days
Backend
Add JournalEntry model, migration · Create constants/schemas/types · JournalRepository + JournalService · Register in factory, wire router, apply rate limits · Write unit tests.
