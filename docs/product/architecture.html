Service Factory (DI Pattern)

Services are lazy-initialized singletons within a request — no DI container required. Factory created in context.ts, passed to all tRPC procedures via ctx.services.

typescriptservices/service.factory.ts
export class ServiceFactory {
  private _characterService?: CharacterService

  get characterService() {
    if (!this._characterService) {
      this._characterService = new CharacterService(this.prisma, this.repositories)
    }
    return this._characterService
  }
}

tRPC Middleware

typescripttrpc.ts — protectedProcedure
export const protectedProcedure = t.procedure.use(async ({ ctx, next }) => {
  if (!ctx.session) throw new TRPCError({ code: 'UNAUTHORIZED' })
  return next({ ctx: { ...ctx, session: ctx.session } })
})

What We Are NOT Doing

Frontend

  • No separate React SPA (Vite)
  • No Astro landing site
  • No Redux / Context API for state
  • No styled-components / emotion
  • No barrel index.ts files
  • No middleware.ts for auth

Backend

  • No DI container (InversifyJS, etc.)
  • No CQRS / command bus / domain events
  • No separate value objects
  • No separate Bun/Fastify process
  • No Supabase — replaced with PostgreSQL + Better Auth
