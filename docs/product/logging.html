Structured Logging

Version 2.0 Implemented Last Updated: 2026-05-08

All server-side logging uses Pino for structured JSON output. A thin client-side wrapper forwards browser logs to the same Pino stream via /api/logs.

Goals

  1. Structured JSON output in production (Railway-compatible)
  2. Pretty-printed colored output in development
  3. Request-scoped logging with user context (userId) in authenticated tRPC requests
  4. Configurable log levels via LOG_LEVEL environment variable
  5. Client logs unified into the same stream as server logs

Architecture

Server Logger

typescriptsrc/server/lib/logger.ts
import pino from 'pino'

const validLevels = ['fatal', 'error', 'warn', 'info', 'debug', 'trace'] as const
const envLevel = process.env.LOG_LEVEL
const nodeEnv = process.env.NODE_ENV as string
const level =
  envLevel && validLevels.includes(envLevel as (typeof validLevels)[number])
    ? envLevel
    : nodeEnv === 'production' ? 'info' : 'debug'

export const logger = pino({
  level,
  ...(nodeEnv !== 'production'
    ? {
        transport: {
          target: 'pino-pretty',
          options: { colorize: true, translateTime: 'SYS:HH:mm:ss.l', ignore: 'pid,hostname' }
        }
      }
    : {})
})
Design Note
Reads process.env directly (not from config.ts) to avoid circular dependency. Dev uses pino-pretty transport. Prod: raw JSON with no transport overhead — one JSON object per line.

Log Levels

LevelDefaultUsage
fatal—Process-ending errors (invalid env, startup failure)
error—Operational errors (auth failures, tRPC handler errors)
warn—Warnings (missing optional config)
infoProductionKey events (server start, cron execution)
debugDev / TestDetailed debugging
trace—Verbose tracing (manual override)

Client-Side Logging

Usage

typescript
import { clientLogger } from '@/lib/logger.client'

// Plain message
clientLogger.info('Sidebar opened')

// With context (Error objects, extra data)
clientLogger.error('Failed to create objective', error)
clientLogger.warn('Stale cache detected', { cacheAge })

Payload Shape

typescriptsrc/shared/schemas/logs.schemas.ts
{
  level: 'error' | 'warn' | 'info'
  message: string          // max 1000 chars
  context?: unknown        // serialised as-is
  timestamp: string        // ISO 8601
  source: 'client'
}

/api/logs Endpoint

MethodPathAuthPurpose
POST/api/logsNoneReceive client log, forward to Pino

Validates payload with clientLogSchema, then calls logger[level]({ source: 'client', timestamp, context }, message). Client logs appear in the same Pino stream tagged with "source":"client".

400 — Invalid Payload
Zod validation failed.
400 — Bad Request
Malformed JSON body.

Rule
Never use console.* directly — use the appropriate logger so all output is structured, filterable, and routed consistently.
