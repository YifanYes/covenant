Deploy Covenant to GCP Cloud Run

Move the Next.js 16 + Prisma + better-auth stack off Railway onto Cloud Run in europe-west1 with one always-on instance. Database re-provisioned on Cloud SQL (no prod users to migrate). Domain stays at Railway registrar, DNS moves to Cloudflare with proxy off day 1 so the CDN/WAF can be flipped on after launch metrics stabilise.

Why migrate

Predictability
Per-resource pricing, no surprise tiers

Cloud Run bills vCPU-seconds, memory-seconds, requests, and egress. With min-instances = 1 the bill is a flat ~$50–55/mo + traffic.

Ecosystem
Cloud SQL, Secret Manager, Logs, IAM

Private VPC connector to Cloud SQL, secrets mounted as env vars, Cloud Logging / Error Reporting wired in by default. Sentry stays — they don't conflict.

Cold starts
Min-instances = 1 kills first-hit latency

One warm container always answering. Next.js boot ≈ 2–3s, painful on serverless free tiers, irrelevant when min = 1.

Why Cloud Run, not Cloudflare

Cloudflare Workers and Pages run on the V8-isolate edge runtime, not Node. The Covenant stack has three hard incompatibilities with that runtime today. Cloudflare's value here is DNS, CDN, and WAF in front of Cloud Run, not as the runtime.

Decision

Cloud Run hosts the app. Cloudflare hosts DNS (proxy off). Revisit Cloudflare proxy + WAF + cache 2 weeks post-cutover. Workers/Pages only revisit if the stack drops node-cron, swaps Prisma adapter, and adopts an edge-compatible auth layer.

GCP one-time setup

Run these once. Replace $PROJECT and $REGION=europe-west1. Commands are illustrative — see Google docs for exact flags.

  1. Create project, link billing.
  2. Enable APIs: 
    gcloud services enable run.googleapis.com sqladmin.googleapis.com \
  artifactregistry.googleapis.com secretmanager.googleapis.com \
  vpcaccess.googleapis.com iam.googleapis.com cloudbuild.googleapis.com
  3. Create Artifact Registry docker repo: 
    gcloud artifacts repositories create covenant \
  --repository-format=docker --location=$REGION
  4. Create Cloud SQL Postgres 16 instance (start small, scale later): 
    gcloud sql instances create covenant-db \
  --database-version=POSTGRES_16 --region=$REGION \
  --tier=db-f1-micro --storage-auto-increase \
  --network=default --no-assign-ip   # private IP only
  5. Create database + user, store password in Secret Manager.
  6. Create Serverless VPC Access connector: 
    gcloud compute networks vpc-access connectors create cr-conn \
  --region=$REGION --range=10.8.0.0/28
  7. Create secrets in Secret Manager — one per env var listed in src/server/config.ts. Use gcloud secrets create $NAME --replication-policy=automatic then versions add.
  8. Create runtime service account: 
    gcloud iam service-accounts create covenant-runtime
# bind: roles/cloudsql.client, roles/secretmanager.secretAccessor,
#       roles/logging.logWriter, roles/monitoring.metricWriter
  9. Create deployer service account: 
    gcloud iam service-accounts create covenant-deployer
# bind: roles/run.admin, roles/iam.serviceAccountUser,
#       roles/artifactregistry.writer, roles/run.invoker on the job
  10. Configure Workload Identity Federation for GitHub OIDC, bind to covenant-deployer. Reference: Google's "Authenticate to Google Cloud from GitHub Actions" guide.
  11. Create Cloud Run service (initial deploy can be from a placeholder image; CI replaces it): 
    gcloud run deploy covenant \
  --image=$REGION-docker.pkg.dev/$PROJECT/covenant/app:bootstrap \
  --region=$REGION --min-instances=1 --max-instances=10 \
  --cpu=1 --memory=1Gi --concurrency=80 --timeout=300 \
  --service-account=covenant-runtime@$PROJECT.iam.gserviceaccount.com \
  --vpc-connector=cr-conn --vpc-egress=private-ranges-only \
  --set-secrets=DATABASE_URL=DATABASE_URL:latest,DIRECT_URL=DIRECT_URL:latest,...
  12. Create Cloud Run Job covenant-migrate with the same image, command override pnpm prisma migrate deploy, same SA + VPC connector + DB secrets.
  13. Map custom domain on Cloud Run (after DNS at Cloudflare exists): 
    gcloud run domain-mappings create --service=covenant \
  --domain=app.example.com --region=$REGION

CI/CD — GitHub Actions

Workflow file .github/workflows/deploy.yml. Push to main → build → push → migrate-job → deploy.

name: deploy
on:
  push:
    branches: [main]

concurrency:
  group: deploy-main
  cancel-in-progress: true

permissions:
  id-token: write
  contents: read

env:
  PROJECT_ID: covenant-prod
  REGION: europe-west1
  REPO: covenant
  IMAGE: app
  SERVICE: covenant
  JOB: covenant-migrate

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - id: auth
        uses: google-github-actions/auth@v2
        with:
          workload_identity_provider: projects/${{ secrets.GCP_PROJECT_NUMBER }}/locations/global/workloadIdentityPools/github/providers/github
          service_account: covenant-deployer@${{ env.PROJECT_ID }}.iam.gserviceaccount.com

      - uses: google-github-actions/setup-gcloud@v2

      - name: Configure Docker auth
        run: gcloud auth configure-docker $REGION-docker.pkg.dev --quiet

      - name: Build & push image
        run: |
          IMG="$REGION-docker.pkg.dev/$PROJECT_ID/$REPO/$IMAGE:${{ github.sha }}"
          docker build -t "$IMG" .
          docker push "$IMG"
          echo "IMG=$IMG" >> $GITHUB_ENV

      - name: Run migrations
        run: |
          gcloud run jobs update $JOB --image "$IMG" --region $REGION
          gcloud run jobs execute $JOB --region $REGION --wait

      - name: Deploy revision
        run: |
          gcloud run deploy $SERVICE \
            --image "$IMG" --region $REGION \
            --min-instances=1 --max-instances=10

Sentry sourcemap upload: add SENTRY_AUTH_TOKEN as a GH Actions secret and let the Sentry webpack plugin run during docker build (already wired in next.config.ts:44-46).

Dockerfile

# syntax=docker/dockerfile:1.7

FROM node:22-alpine AS deps
WORKDIR /app
RUN apk add --no-cache libc6-compat openssl
RUN corepack enable
COPY package.json pnpm-lock.yaml ./
COPY prisma ./prisma
RUN pnpm install --frozen-lockfile

FROM node:22-alpine AS builder
WORKDIR /app
RUN apk add --no-cache libc6-compat openssl
RUN corepack enable
COPY --from=deps /app/node_modules ./node_modules
COPY . .
ENV NEXT_TELEMETRY_DISABLED=1
RUN pnpm prisma generate
RUN pnpm build

FROM node:22-alpine AS runner
WORKDIR /app
RUN apk add --no-cache libc6-compat openssl
ENV NODE_ENV=production NEXT_TELEMETRY_DISABLED=1 PORT=8080
RUN addgroup -S app && adduser -S app -G app
COPY --from=builder /app/public ./public
COPY --from=builder --chown=app:app /app/.next/standalone ./
COPY --from=builder --chown=app:app /app/.next/static ./.next/static
COPY --from=builder /app/prisma ./prisma
COPY --from=builder /app/node_modules/.prisma ./node_modules/.prisma
USER app
EXPOSE 8080
CMD ["node", "server.js"]

Standalone server file is emitted by Next 16 when output: 'standalone' is set. The openssl and libc6-compat packages are required by Prisma's query engine on Alpine.

Cutover runbook

  1. Run CI on main: build, push, run migrate job against empty Cloud SQL.
  2. Hit Cloud Run service URL (https://covenant-XXXX-ew.a.run.app) and smoke-test: /api/health returns 200, sign-up with email works, Google OAuth callback works (after adding the Cloud Run URL as authorised redirect URI in Google Cloud Console).
  3. Update NEXT_PUBLIC_APP_URL + better-auth trustedOrigins + email FROM_URL to the final domain. Redeploy.
  4. In Cloudflare, add a site for the domain. Cloudflare gives two nameservers.
  5. In Railway domain settings, change the domain's nameservers to Cloudflare's. This is the irreversible-looking but reversible step. TTL of the NS record at the registry level is typically 48h.
  6. In Cloudflare DNS panel, add records that Cloud Run gives you after gcloud run domain-mappings describe. Set proxy to DNS only (grey cloud). Use TTL 300s during cutover.
  7. Wait for Cloud Run managed cert to issue (5–30 min). Verify https://app.example.com/api/health returns 200.
  8. Update Google OAuth redirect URI to the final domain. Sign-in end-to-end test.
  9. Raise DNS TTL to 3600 after stability is confirmed.
  10. Leave the Railway service paused (not deleted) for 7 days as instant rollback.

Rollback

  • Bad Cloud Run revision: gcloud run services update-traffic covenant --to-revisions=PREV_REV=100 --region=$REGION — instant.
  • Bad cutover (DNS or domain mapping): revert Cloudflare records to point at Railway's CNAME. Propagates in TTL window.
  • Bad migration: migrations are forward-only. Cloud SQL has automated daily backups + 7-day PITR — restore from the latest pre-migration timestamp into a new instance, swap the secret DATABASE_URL, redeploy.
  • Total abandon: change Cloudflare nameservers back to Railway's at the Railway registrar; un-pause the Railway service.

Open questions / follow-ups

Cloudflare proxy flip

Default plan: enable orange-cloud + Bot Fight Mode 2 weeks post-cutover. Tighten Cloud Run ingress to "internal + LB" and allow-list Cloudflare IPs.

Registrar transfer

Move from Railway to Cloudflare for at-cost renewals (~$8/yr .com). Requires unlock + auth code + 5-7 day wait. Background task.

node-cron

Dep present, no callers found in src/. If real cron jobs are added, move them to Cloud Scheduler → Cloud Run Job — do not keep them inside the request-serving container.

Sentry sourcemaps

Wire SENTRY_AUTH_TOKEN as a GH Actions secret; verify uploads land per release after first deploy.
